## 二、现有 DOCX 评审表内容摘要

《27机械图纸评审表》结构如下：

1. **会议基本信息**：评审主题、时间、组织方、会议形式（腾讯会议）、会议号/入会链接
2. **评审对象**：图纸编号、版本号、图纸名称、设计人、所属项目、所属模块
3. **参会人员**：14 人签到表（姓名、部门/SIG、角色、评审意见）
4. **评审检查项**（10 项）：
   - 设计需求符合性
   - 结构合理性
   - 尺寸与公差
   - 材料与选型
   - 加工工艺性
   - 装配与维护
   - 机电接口
   - 强度与安全
   - BOM 完整性
   - 文档规范
5. **问题记录与整改**：问题描述、提出人、责任人、完成期限
6. **评审结论**：通过 / 有条件通过 / 不通过

### 3.2 现有流程与 PRD 的核心差异

| 维度 | 现有流程 | PRD 目标流程 |
|------|---------|-------------|
| 形态 | 线下/半线下模板文档 | 数字化、端到端工作流 |
| 触发方式 | 人工发起会议、人工填表 | 图纸提交后自动触发评审、会议、下游流程 |
| 数据结构化 | 弱（DOCX/空 Base） | 强（图纸评审单、BOM、评估报告、发货清单等实体） |
| 系统集成 | 无 | 腾讯会议、ERP、MES、日历、邮件/飞书消息 |
| 自动化程度 | 低 | 高（会议自动预约、BOM 自动生成、库存自动拉取） |
| 可追溯性 | 依赖人工归档 | 全流程版本关联与状态看板 |
| 角色权限 | 无明确权限控制 | 设计/电控/布线/采购/生产/仓储/项目经理等角色矩阵 |

## 五、结论

**现有流程与 PRD 设想存在明显差距：**

- 现有「27机械图纸评审表」本质上是一份**线下会议记录模板**，仅覆盖了 PRD 中「评审会议」和「会议纪要」的表单内容，但完全没有数字化流转、自动触发、系统集成等能力。
- 现有的项目管理 Base、进销存 Base、采购申请 Base 都是**相互独立的模板/工具**，未与图纸评审流程打通，也未形成端到端闭环。
- PRD 中设想的**自动会议预约、BOM 自动生成、电控/布线评估、库存/MES 拉取、发货清单自动生成、成员排期、机械加工件 BOM、三家询价单、统一流程看板**等关键能力，目前在飞书空间中均未找到对应实现。

**建议实施路径：**

1. **MVP 阶段**：以「27机械图纸评审表」DOCX 内容为起点，先在飞书多维表格中构建「图纸评审单」+「会议纪要」+「问题清单」三张表，替代现有线下文档。
2. **集成阶段**：接入腾讯会议 API 实现自动预约，接入日历实现成员排期。
3. **扩展阶段**：逐步叠加 BOM 生成、电控/布线评估、库存拉取、发货清单、采购三家询价、流程看板。
