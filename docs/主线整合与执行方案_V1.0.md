## 3. 事故复盘与历史恢复（务必阅读）

### 3.1 发生了什么
`nec-hub` 与 `nec-hub-latest` 实为**同一仓库的两个 git worktree**（共享一个 `.git`）。main 归档删除 `nec-hub` 时，主仓库 `.git` 被连带删除，导致 fix/vi 分支从未推送远端的约 40 条本地提交**粒度丢失**。

### 3.2 已恢复的内容
- **代码零损失**：工作区全量已在 `33c6b45` 以快照形式重建提交（父 = main `32c0b98`），历史链 = main 全史 + fix/vi 快照；与生产部署完全一致，200 用例全绿。
- **main 全史与归档 tag**：gitee/GitHub 双份齐全。

### 3.3 可选找回（有窗口期）
丢失的 fix/vi 中间提交粒度，唯一找回途径是 **OneDrive 网页回收站**（约 30 天）恢复 `nec-hub` 文件夹的 `.git`。若需要完整 40 条提交史，请尽快操作，恢复后可在其上做历史嫁接（graft）。不找回也不影响任何代码与运行。

## 7. 多 Agent 协作公约（本仓库已有多窗口并行开发的现实）

1. **提交门禁**：任何提交前必须 `npm run check` + `npm test` 全绿（当前 200 用例基线）。
2. **提交即推送**：commit 后立即 `git push gitee`；本仓库发生过一次未推送即丢失，此条为红线。
3. **动文件前先拉现状**：另一个窗口可能正在改同一文件（本晚已两次半成品撞车）；动手前 `git status` + 读文件再编辑，发现半成品先补完而不是从旧基线覆盖。
4. **分工声明**：开工时在群内说一句"我拿 X 模块"，同一模块同一时间只允许一个会话写。
5. **GitHub 镜像**：网络不稳时以 gitee 为唯一事实源，镜像尽力推、失败留记录（对照文档文尾有台账）。
