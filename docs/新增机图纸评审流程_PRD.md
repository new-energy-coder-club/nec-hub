## 1. 背景与目标

### 1.1 背景
当前新增机型的图纸评审依赖线下邮件、微信群、个人日历和 Excel 手工汇总，存在以下问题：
- 评审会议需人工预约，容易遗漏关键成员；
- 会议纪要、评审结论散落，难以追溯；
- BOM、电控评估、布线评估与后续采购、生产、发货脱节；
- 库存数据、MES 位置、加工件 BOM、询价单等需跨系统手工搬运；
- 流程节点不透明，项目排期依赖口头沟通。

### 1.2 目标
建设「新增机图纸评审流程」数字化工作流，实现：
1. 图纸报告书在线提交与版本管理；
2. 腾讯会议自动预约并自动勾选相关成员；
3. 会议纪要、评审结论结构化保存并关联图纸版本；
4. 评审通过后自动触发 BOM 工程量清单、电控评估、布线评估；
5. 拉取库存与 MES 位置，自动生成发货清单；
6. 基于成员时间清单自动排期；
7. 同步机械加工件 BOM 并生成三家询价单；
8. 提供流程管理看板，实时查看流程状态与阻塞点。

## 3. 功能模块详细设计

### 3.1 图纸报告书提交

#### 3.1.1 输入内容
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 项目编号 | 文本 | 是 | 关联项目主数据 |
| 机型名称 | 文本 | 是 | 新增机名称 |
| 图纸版本 | 文本 | 否 | 如 V1.0、V1.1；系统自动推荐最新版本（如已有 V1.0 则推荐 V1.1） |
| 设计负责人 | 人员 | 否 | 机械设计负责人；默认为当前登录用户 |
| 图纸文件 | 附件 | 是 | 支持 DWG/PDF/STEP/ZIP |
| 设计说明 | 富文本 | 否 | 关键设计参数、变更点；系统提供模板 |
| 关联标准件清单 | 表格 | 否 | 预填的标准件参考 |
| 预计加工周期 | 数字 | 否 | 天 |
| 预计装配周期 | 数字 | 否 | 天 |

#### 3.1.2 业务规则
- 同一项目同一机型，图纸版本需递增；
- 图纸提交后自动锁定，如需修改需走「变更申请」；
- 提交成功后向设计负责人、项目经理发送通知。

### 3.1.3 自动默认填写功能
系统提供智能默认值填充，提升用户体验：
- **图纸版本**：自动检测同一项目和机型的最新版本，并推荐下一个版本号（如 V1.0 → V1.1）
- **设计负责人**：默认设置为当前登录用户
- **设计说明**：提供结构化模板，包含设计背景、关键技术参数、主要变更点等标准章节
- **项目编号/机型名称**：可从用户最近操作中智能推荐

### 3.1.4 开始填写（方便填写）
提供专用 API 端点获取预填充的默认值，支持前端快速初始化表单：
- **Endpoint**: `GET /api/drawing-review/start`
- **Response**: JSON object with default values for all fields
- **Features**: 
  - Returns user-specific preferences (last used project, machine, version)
  - Includes smart version recommendations
  - Provides template-based design notes
  - Supports frontend form auto-population

### 3.1.5 图纸联想功能

提供基于历史数据和上下文的智能联想，提升表单填写效率：
- **实时联想**：输入时自动显示相关建议（项目编号、机型名称）
- **上下文感知**：根据当前表单内容调整联想结果
- **任务关联**：与现有任务数据关联，推荐相关项目和机型
- **智能排序**：按相关性和使用频率排序联想结果
- **键盘支持**：完整的键盘导航和快捷键支持

> **实现状态：✅ 已上线（2026-10-14 深夜）**。`src/drawing-review/suggestion.service.ts`（项目编号/机型名称/基于任务的智能联想，结果去重、按相关性与使用频率排序）+ API `GET /api/drawing-review/suggestions`（通用联想）、`GET /api/drawing-review/{id}/task-suggestions`（任务关联联想）；门户提交表单实时联想输入框 + 键盘导航（↑↓ 选择、Enter 确认、Esc 关闭）+「加载默认值」一键填充；`adapter.ts` 新增 `findReviewsByPattern` / `getProjectSuggestions` / `getMachineSuggestions`；45 用例 100% 通过（`suggestion.service.test.ts` + `integration.test.ts`），12 篇用户/开发/运维文档归档 docs/（索引见《文档目录索引》）。待办：独立应用页（`public/apps/drawing-review/`）暂未同步联想输入，属于"双实现漂移收敛"工作（见《页面与Tab状态现状》P1-3）。

#### 3.1.6 用户偏好学习
系统自动学习用户填写习惯，提供个性化默认值：
- **自动记忆**：记录用户最近使用的项目编号、机型名称、版本号
- **智能推荐**：基于历史数据推荐最可能的 values
- **模板选择**：支持不同设计说明模板（V1/V2）
- **隐私保护**：所有偏好数据存储在用户专属密钥空间

#### 3.1.7 输出
- 生成「图纸评审单」唯一编号（如 DR-20261013-001）；
- 状态更新为「待评审」。

### 3.2 腾讯会议自动预约

#### 3.2.1 触发条件
图纸报告书提交并通过完整性校验后，系统自动预约评审会议。

#### 3.2.2 会议参数
| 参数 | 来源/默认值 |
|------|------------|
| 会议主题 | 「新增机图纸评审」-{机型名称}-{图纸版本} |
| 会议时间 | 提交后 T+1 工作日的默认时段（可配置） |
| 会议时长 | 默认 60 分钟，可根据图纸复杂度动态调整 |
| 参会成员 | 系统自动勾选，见 3.2.3 |
| 会议描述 | 自动带入图纸版本、设计说明摘要、评审单链接 |

#### 3.2.3 自动勾选成员规则
| 角色 | 是否默认勾选 | 说明 |
|------|-------------|------|
| 设计负责人 | 是 | 提交人 |
| 机械评审专家 | 是 | 按机型匹配专家库 |
| 电气/电控负责人 | 是 | 需参与电控评估 |
| 布线工艺工程师 | 是 | 需参与布线评估 |
| 采购代表 | 是 | 需评估采购可行性 |
| 生产/装配负责人 | 是 | 需评估加工与装配周期 |
| 项目经理 | 是 | 流程Owner |
| 质量工程师 | 条件勾选 | 涉及关键质量特性时 |
| 仓储/物流 | 条件勾选 | 涉及库存与发货时 |

#### 3.2.4 集成方式

> **实现变更（2026-10-14 深夜）**：会议系统由腾讯会议 OpenAPI 改为**飞书视频会议 API**（`open.feishu.cn/open-apis/vc/v1`，经共享服务 `src/shared/meeting.service.ts`，MCP `schedule_meeting` 同源）；未开通 `vc:meeting:write` 权限时自动降级返回 mock 会议信息（不破坏状态机、允许人工补录）；硬件评审（`/api/hardware-review/{id}/meeting`）复用同一服务。原腾讯会议方案保留为可选接入（见 §4 集成接口清单，优先级调整为 P1）。

- 调用飞书视频会议 API（原腾讯会议 OpenAPI）：创建会议、添加参会人、设置会议提醒；
- 在系统中保存会议 ID、会议链接、参会人列表；
- 会议开始前 15 分钟向未确认成员发送提醒。

### 3.3 会议纪要及评审结论保存

#### 3.3.1 会议纪要模板
| 模块 | 内容 |
|------|------|
| 基本信息 | 评审单号、机型、图纸版本、会议时间、参会人 |
| 议题 | 按预设议题清单勾选 |
| 讨论记录 | 富文本，支持图片/附件 |
| 问题清单 | 问题描述、责任人、截止日期、严重等级 |
| 评审结论 | 通过 / 有条件通过 / 不通过 |
| 下一步动作 | 动作、负责人、截止时间 |

#### 3.3.2 评审结论类型
- **通过**：进入下一流程节点（BOM 生成）。
- **有条件通过**：需记录整改项，整改完成后自动流转。
- **不通过**：退回设计负责人修改，重新触发评审。

#### 3.3.3 自动关联
- 会议纪要自动关联腾讯会议录制（如有）；
- 评审结论与图纸版本绑定，支持历史版本追溯。

### 3.7 库存数据与 MES 位置拉取

#### 3.7.1 数据来源
- **库存数据**：ERP/WMS 库存查询接口；
- **MES 位置**：MES 系统中物料的库位、工位、在制状态。

#### 3.7.2 拉取规则
- 按 BOM 物料编码批量查询库存；
- 区分自有库存、在途库存、在制库存、缺料；
- 标注物料所在仓库/库位/MES 工位。

#### 3.7.3 输出
| 状态 | 说明 |
|------|------|
| 库存充足 | 可直接出库 |
| 库存不足 | 需采购/生产 |
| 无库存 | 需新采购或新加工 |
| 在制 | 需跟踪完工日期 |

### 3.9 成员时间清单与排期

#### 3.9.1 时间清单来源
- 同步企业日历/飞书/腾讯会议成员日程；
- 读取成员任务负载（可选接入项目管理系统）。

#### 3.9.2 排期逻辑
1. 获取各节点负责人可用时段；
2. 结合加工周期、采购周期、装配周期；

## 13. 验收标准

每个核心模块给出可验证的验收条件，作为联调与验收测试的核对清单。

### 13.1 图纸报告书提交（对应 3.1）
1. Given 填写完整的图纸报告书表单，When 点击提交，Then 5 秒内生成 `DR-` 前缀唯一编号评审单，状态置为 `pending_review`（待评审）。
2. Given 同一项目同一机型已存在 V1.0，When 打开提交表单（`GET /api/drawing-review/start`），Then 图纸版本字段自动推荐 V1.1。
3. Given 缺少必填字段（项目编号/机型名称/图纸文件），When 提交，Then 接口返回 400 并指明缺失字段，不产生评审单。
4. Given 提交成功，Then 设计负责人与项目经理收到通知，且事件日志表新增一条 `submit` 记录。

### 13.2 会议自动预约（对应 3.2；实现以飞书视频会议为主，腾讯会议为备选，见 §3.2.4 变更注）
1. Given 评审单通过完整性校验，When 触发预约，Then 会议主题为「新增机图纸评审」-{机型}-{版本}，会议 ID 与链接写回评审单。
2. Given 机型匹配的成员规则，When 创建会议，Then 3.2.3 表中默认勾选角色全部在参会人列表内。
3. Given 会议时间前 15 分钟，When 存在未确认成员，Then 系统向未确认成员发送提醒。
4. Given 会议 API 调用失败（或 `vc:meeting:write` 权限未开通走降级 mock），Then 评审单状态不被破坏，事件日志记录失败原因，允许人工补录会议信息。

### 13.3 会议纪要及评审结论（对应 3.3）
1. Given 评审会结束，When 保存纪要与结论，Then 纪要与当前图纸版本绑定，可在评审详情中回看。
2. Given 结论为「不通过」，When 保存，Then 评审单状态必须退回 `draft` 并记录退回原因，禁止直接进入下游节点。
3. Given 结论为「有条件通过」，When 保存，Then 状态置为 `rectifying`（待整改），整改项清单必填，整改完成事件触发后自动流转至 BOM 生成。
4. Given 任意状态，When 尝试非法流转（如 `draft` 直接归档），Then 状态机拒绝并返回错误提示。

### 13.4 BOM 工程量清单（对应 3.4）
1. Given 评审结论为通过（或待整改完成），When 触发 BOM 生成，Then 10 秒内生成 L1-L4 层级 BOM，状态流转至 `assessing`。
2. Given BOM 生成完成，Then 每条物料包含物料编码/名称/数量/来源/工艺等 3.4.3 必填字段，缺字段的条目被标记待补全。
3. Given BOM 已生成，Then 采购、生产、仓储相关角色可在各自视图看到该 BOM。

### 13.5/13.6 电控评估与布线评估（对应 3.5/3.6）
1. Given BOM 生成完成，When 电控负责人提交评估报告，Then 评估结果（pass/fail）与评估人、时间一并记录。
2. Given 电控评估 fail，When 保存，Then 流程退回 `draft` 并通知电气负责人修改；不得进入布线评估。
3. Given 布线评估完成，When 保存线束 BOM，Then 线束条目合并入总 BOM 且可区分来源为「布线」。
4. Given 评估中状态，Then 看板显示 `assessing`，并标注当前待办人为电控/布线负责人。

### 13.7 库存数据与 MES 位置拉取（对应 3.7）
1. Given BOM 物料清单，When 触发库存拉取，Then 按物料编码批量返回库存充足/不足/无库存/在制四种状态之一。
2. Given ERP/MES 接口未就绪，When 使用手动导入模板上传库存数据，Then 系统按相同状态口径展示并标注数据来源为「手动导入」。
3. Given 物料命中库存，Then 记录其仓库/库位/MES 工位信息，供发货清单引用。

### 13.8 发货清单生成（对应 3.8）
1. Given BOM + 库存数据齐备，When 生成发货清单，Then 齐套物料按批次分组并生成系统自动编号的发货批次。
2. Given 存在缺料物料，Then 缺料单独列示并标注预计到货时间，不混入齐套批次。
3. Given 大件/易损件，Then 清单中包装方式与运输方式字段必填。

### 13.9 成员时间清单与排期（对应 3.9）
1. Given 各节点负责人与周期数据，When 生成排期，Then 输出含关键路径的项目排期表（甘特图数据）。
2. Given 成员日程冲突，When 生成排期，Then 冲突时段高亮提示，且支持人工调整后重算。
3. Given 排期确认，When 项目经理点击确认，Then 状态流转至 `procuring`。

### 13.10 机械加工件 BOM 同步（对应 3.10）
1. Given 总 BOM，When 触发加工件同步，Then 仅筛选来源为「自制」且工艺为机加/钣金/焊接的物料生成加工件 BOM。
2. Given 加工件 BOM 生成，Then 同步推送至 MES/生产排程并生成加工任务单草稿，事件日志留痕。

### 13.11 采购三家询价单（对应 3.11）
1. Given BOM 中库存不足的外购/标准件，When 触发询价，Then 每个物料推荐 3 家供应商并生成询价单号。
2. Given 供应商报价回填 ≥ 1 家，When 触发比价，Then 系统按价格与交期生成「采购建议书」。
3. Given 审批通过，Then 生成采购订单，状态流转至 `archived` 前的最后采购节点。

### 13.12 流程管理看板（对应 3.12）
1. Given 存在多个评审单，When 打开看板，Then 按 3.12.2 状态定义正确分桶展示，且与多维表格中的状态一致。
2. Given 当前登录用户有待办节点，Then 「我的待办」视图准确列出该用户负责的评审单。
3. Given 节点超时/缺料/人员冲突，Then 阻塞预警区出现对应条目并可点击跳转评审详情。

## 14. 用户体验设计

### 14.1 双入口关系
| 入口 | 位置 | 说明 |
|------|------|------|
| 门户 Tab | `hub.newenergycoder.club` 门户「图纸评审」Tab | 登录后可见，以嵌入方式展示独立应用页，与应用广场/资料页等 Tab 同权并列 |
| 独立应用页 | `public/apps/drawing-review/`（部署后经 Worker 托管访问） | 独立 HTML 应用，可直接访问或嵌入飞书 WebView，作为门户 Tab 的内容来源 |

原则：两个入口共用同一套后端 API（`/api/drawing-review/*`）与同一份飞书多维表格数据，不维护两套业务逻辑；门户 Tab 负责导航与登录态，独立应用页负责业务交互。

### 14.2 关键页面清单
| 页面 | 核心内容 | 对应模块 |
|------|----------|----------|
| 提交表单页 | 图纸报告书表单（3.1.1 字段）、默认值预填、附件上传 | 3.1 |
| 评审详情页 | 评审单信息、会议信息、纪要/结论、BOM、评估报告、事件时间线 | 3.2-3.6 |
| 流程看板页 | 流程总览、我的待办、节点状态、阻塞预警 | 3.12 |
| 甘特图视图 | 项目排期、关键路径、冲突高亮 | 3.9 |
| 询价/发货视图 | 询价单列表与比价、发货清单批次 | 3.11/3.8 |

### 14.3 关键交互规则
- **状态筛选**：看板顶部提供状态筛选器，选项与 3.12.2 状态定义一一对应；默认展示「我相关的」评审单，可切换到「全部」。
- **结论弹窗**：保存评审结论时使用弹窗二次确认；结论为「不通过」时退回原因必填，「有条件通过」时至少填写 1 条整改项，否则禁止提交。
- **BOM JSON 导入**：支持粘贴/上传 BOM JSON 批量导入，导入前做字段校验（缺必填字段的行逐条报错，不允许部分静默丢弃），导入结果以成功/失败行数摘要反馈。
- **非法操作拦截**：不满足状态机流转条件的操作按钮置灰并附原因提示（如「评审通过后才能生成 BOM」），不依赖后端报错兜底。

### 14.4 响应式与飞书 WebView 兼容
- 页面需同时适配桌面浏览器与飞书移动端 WebView（iOS/Android）；看板与表格在小屏下允许横向滚动，关键操作按钮不被裁剪。
- 遵守飞书 WebView 版本要求（主题背景等特性按飞书 V5.12+/V5.14+/V7.9+ 要求适配，与中台门户一致）。
- 交互以文字与表单为主，不依赖拖拽等移动端体验差的操作完成关键流程。

## 16. 上线与部署

### 16.1 部署方式
- 部署目标：Cloudflare Worker，执行 `npm run deploy`（经 `scripts/deploy-hub.sh`）发布。
- 访问入口：自定义域名 `hub.newenergycoder.club`，门户「图纸评审」Tab 与 `/api/drawing-review/*` 随主站一同发布，无独立部署单元。

### 16.2 配置步骤
1. 在飞书创建图纸评审专用多维表格，按 10 张逻辑表（评审单/会议纪要/整改项/BOM/评估报告/库存查询/发货清单/排期任务/询价单/事件日志）建表并记录 table_id。**（已完成，2026-10-14：Base `OFZqbJHteaYRpssam7Nc4fTYnLc`，table_id 清单见设计文档 §5.1.1）**
2. 调用 MCP `config_drawing_review`（或 `POST /api/drawing-review/config`）写入 base 与 10 张 table_id。**注意 set 为全量覆盖，须一次带齐全部 table_id。**
3. 调用 `GET /api/drawing-review/config` 验证配置生效，随后提交一条测试评审单走通链路。
4. 配置 `FEISHU_WEBHOOK_URL`（飞书群自定义机器人）：配置后评审单提交/状态流转/报价回填/供应商选定实时推送群通知，每小时 cron 自动推送看板阻塞告警；未配置则全部静默跳过，不影响主流程。
5. 未配置时 API 返回明确提示（「请先调用 POST /api/drawing-review/config 设置 base 与 tables」），不出现 500。

### 16.3 灰度策略
- 先试点 1 个真实新增机项目跑通全链路，期间仅项目组开放使用；
- 试点期间腾讯会议/ERP/MES 未联调的环节用手动导入模板兜底，不阻塞主流程；
- 试点复盘通过后向全部新增机项目推广。

### 16.4 回滚方案
- **代码回滚**：Worker 按版本保留，异常时回滚至上一版本（wrangler 版本回滚能力），5 分钟内完成。
- **功能开关**：门户图纸评审 Tab 可通过注册表配置下线（门户恢复六 Tab），数据仍保留在飞书多维表格，恢复入口即恢复使用。

### 16.5 监控
- 健康检查：`GET /api/health` 用于存活探测。
- 事件日志：所有状态流转与关键操作写入「事件日志」表，作为审计与排障依据。
- 告警：飞书 API 限流/接口连续失败时在看板暴露异常提示。

## 17. 培训与支持

### 17.1 各角色 5 分钟上手要点
| 角色 | 上手要点 |
|------|----------|
| 设计负责人 | 门户 → 图纸评审 → 新建提交；版本号与设计说明用系统推荐值，改完直接提交 |
| 机械评审专家 | 收到会议邀请即参会；会后打开评审详情按模板填纪要与结论 |
| 电控/布线负责人 | 看板「我的待办」出现评估任务 → 打开详情 → 填评估报告并选 pass/fail |
| 采购代表 | 待办中出现询价单 → 确认 3 家供应商 → 回填报价 → 查看系统比价建议 |
| 生产/装配负责人 | 查看加工件 BOM 与甘特图，冲突时段直接反馈项目经理 |
| 仓储/物流 | 发货清单按批次出库，缺料项关注预计到货时间 |
| 项目经理 | 每天看板扫一遍阻塞预警；催办直接点进评审详情留言 |

### 17.2 FAQ
1. **图纸传错了怎么办？** 提交后图纸自动锁定，需走「变更申请」解锁修改；未评审前也可由项目经理退回至 `draft` 重新上传。
2. **会议没有自动约上怎么办？** 先查事件日志表中的预约失败原因（常见为 API 权限不足）；可由人工在腾讯会议建会后把会议 ID/链接补录进评审单，流程不受影响。
3. **询价供应商不够 3 家怎么办？** 系统按历史采购推荐 3 家，供应商库不足时采购代表可手动添加候选；最终不足 3 家的询价单需采购负责人在比价建议中注明原因。
4. **评审结论填错了能改吗？** 结论保存即驱动状态机流转，不可直接编辑；填错由项目经理走退回/重新评审路径纠正，所有变更在事件日志留痕。
5. **ERP/MES 接口没好之前库存怎么拉？** 使用手动导入模板上传库存快照，系统按同一口径展示并标注来源为「手动导入」，接口就绪后无缝切换。
6. **看板状态和多维表格对不上怎么办？** 看板实时读取多维表格，如有延迟先刷新；持续不一致时查事件日志确认最后一次流转事件。

### 17.3 支持渠道
- 首选：战队飞书群（图纸评审流程专项话题），工作日响应。
- 文档：中台门户「资料页」Tab 的 SOP 区（评审流程操作说明与模板）。
- 配置类问题（表结构、字段映射）找系统管理员处理。

## 18. 合规与安全

### 18.1 图纸文件保密
- 图纸文件（DWG/PDF/STEP/ZIP）按企业保密要求存储，附件加密存储，仅评审相关角色可访问；外发（供应商询价附图）需采购负责人确认范围。
- 附件 URL 不对外公开，访问需登录态校验。

### 18.2 飞书数据权限（数据不下沉原则）
- 业务数据只存飞书多维表格，Worker 侧不留存业务副本；缓存仅作性能优化且带过期时间。
- 权限复用飞书体系，角色取自"队员名单"多维表格，不自建账号体系；队员被移出名单后会话即时失效。

### 18.3 操作留痕
- 所有状态流转、结论保存、BOM/询价/发货关键操作写入「事件日志」表（操作人、时间、前后状态、原因），日志只增不改，作为审计依据。

### 18.4 财务/询价数据脱敏
- 供应商报价、采购金额等财务敏感数据按角色脱敏：仅采购代表/项目经理/财务角色可见明细，其余角色仅见汇总或无权访问，与中台财务报销表的三级脱敏策略（hidden/summary/full）保持一致。
- MCP 查询涉及询价/财务表时强制鉴权（有效 token + 角色校验）。
