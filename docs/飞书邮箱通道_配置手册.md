# 「G-05 邮件通道」飞书邮箱配置手册

> 配套文档：[PRD_审批与通知中心_V1.2_缺口补齐.md](PRD_审批与通知中心_V1.2_缺口补齐.md) §7（G-05 邮件通道，飞书邮箱 OpenAPI 方案）
> 前置条件：操作人需为飞书企业**管理员**（第 1、2 步）+ 本中台 Worker 的维护者（第 4 步起）。
> 预计耗时：15–30 分钟（不含企业管理员审批等待）。

---

## 总览：配置链路

```
企业开通飞书邮箱 → 开发者后台开通 mail scope → 发信人重新登录门户（覆盖授权）
→ wrangler secret 配置 → （可选）流程级收件人 mailTo → 验证发信
```

代码侧已就绪：`src/feishu/mail.ts`（发信）+ `src/notify.ts`（双通道调度）+ 门户登录/任务重绑授权链接已包含 `mail:user_mailbox.message:send`（2026-10-15 起）。**配置未完成时邮件通道自动降级为 disabled，不影响任何现有功能**——可以按本手册从容配置。

## 第 1 步：企业开通飞书邮箱（企业管理员）

1. 浏览器打开飞书管理后台：`https://feishu.cn/admin`
2. 左侧导航选择 **邮箱**（或「工作台 → 邮箱」），按指引开通企业邮箱服务
3. 为发信人账号分配邮箱地址：
   - **个人邮箱**（推荐先跑通）：直接用队长/值班同学自己的邮箱，如 `zhangsan@<企业域名>`；
   - **公共邮箱**（推荐正式使用）：在「邮箱 → 公共邮箱」新建如 `nec-hub@<企业域名>`，并把发信人加为可使用成员——系统通知从公共邮箱发出更规范，发信人离职也不影响通道。
4. 确认收件人（队员/财务等）均已有企业邮箱地址，否则邮件发不出去。

## 第 2 步：开发者后台开通 mail scope（企业管理员 / 应用创建者）

1. 打开飞书开放平台：`https://open.feishu.cn/app`，进入本中台自建应用（与 `FEISHU_APP_ID` 对应的那个）
2. 左侧 **权限管理** → 搜索并开通以下权限：

   | 权限 | scope | 用途 |
   |---|---|---|
   | 发送邮件 | `mail:user_mailbox.message:send` | 创建草稿 + 发送草稿（邮件通道唯一必需权限） |

3. 若用公共邮箱发信，同一页面确认应用的**数据权限范围**覆盖该公共邮箱（或发信人是其可使用成员）。
4. 左侧 **版本管理与发布** → **创建版本** → 提交发布；企业若开启了应用审核，等管理员在管理后台通过后权限才生效。

> 验证方式：发布生效后，在「权限管理」页搜索 `mail:user_mailbox.message:send` 应显示"已开通"。

## 第 3 步：发信人重新登录门户（覆盖授权）

> 原因：邮件通道用 **user_access_token** 发信（谁授权就以谁的邮箱发出）。授权是在登录时完成的，旧登录态不含 mail scope，必须重新授权一次。

1. 打开中台门户 `https://hub.newenergycoder.club`，右上角**退出登录**再点**飞书登录**；
2. 授权页会多出「发送邮件」权限项，点击同意；
3. 登录成功即完成覆盖授权——KV 中 `feishu:user_token:<open_id>` 已带 mail scope（后续由 `src/feishu/user-token.ts` 自动续期，无需再操作）。

**记录发信人的 open_id**（第 4 步要用），获取方式任选：
- 登录后浏览器开发者工具看 `/api/auth/login` 响应里的 `open_id`（`ou_` 开头）；
- 或在飞书通讯录里点该成员详情查看。

> 若该成员之后在门户「我的任务」里点了「重新绑定」，授权同样含 mail scope（两处授权链接已对齐），不会丢权限。

## 第 4 步：配置 Worker secrets（Worker 维护者）

在中台项目根目录执行：

```bash
# 必填：发信人 open_id（第 3 步记录的 ou_ 开头 ID）
npx wrangler secret put MAIL_SENDER_OPEN_ID

# 可选：默认收件人（逗号分隔），流程未配 mailTo 时的兜底
npx wrangler secret put MAIL_TO

# 可选：EML From 头（默认省略，由发信邮箱主地址填充）
npx wrangler secret put MAIL_FROM

# 可选：发信邮箱（默认 me = 授权人主邮箱；用公共邮箱时填公共邮箱地址）
npx wrangler secret put MAIL_MAILBOX
```

配置后执行 `npx wrangler deploy` 生效（secret 变更不自动重建部署）。

## 第 5 步（可选）：按流程配置收件人

收件人优先级：**流程 `mailTo` > env `MAIL_TO`**，全空则该流程不发邮件（群通知不受影响）。

通过 MCP 工具 `config_flows` 配置（需管理端 MCP_TOKEN）：

```json
{
  "action": "set",
  "flows": {
    "reimburse": { "mailTo": ["finance@<企业域名>", "captain@<企业域名>"] },
    "hardware": { "mailTo": ["hardware-lead@<企业域名>"] }
  }
}
```

建议配置：
- **报销**：财务 + 队长（审批结果留邮件凭证）；
- **图纸/硬件/合规**：对应组组长，或暂不配（只走群通知）。

## 第 6 步：验证

按 PRD V1.2 §7.3 五条验收用例执行：

1. **通道自测**（不依赖审批单）：MCP 调 `send_notice` —
   ```json
   { "flow": "reimburse", "title": "邮件通道自测", "content": "G-05 配置验证", "channel": "mail", "to": "你自己的邮箱" }
   ```
   返回「✅ 邮件已发送」且收件箱收到 HTML 邮件即通。
2. **双通道实测**：随便 approve 一单报销 → 群通知照收，同时 `mailTo` 收件人收到审批结果邮件（含申请人/类型/审批意见/详情链接）。
3. **降级验证**：临时把 `MAIL_SENDER_OPEN_ID` 删掉 redeploy → 邮件调用返回 disabled 说明，群通知与审批流不受影响（测完记得配回）。
4. **失败留痕**：若发信失败，查 KV `notify:failed` 应有 `flow=mail` 的记录。

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回「邮件通道未启用（未配置 MAIL_SENDER_OPEN_ID）」 | 第 4 步未做或未 deploy | `wrangler secret put` 后重新部署 |
| 返回「发信人未完成 OAuth 授权或授权已失效」 | 发信人未重新登录（第 3 步），或 refresh_token 过期 | 让发信人重新登录门户；超过 30 天未活跃需重新授权 |
| 创建草稿失败 `99991672` 类权限错误 | 应用未开通/未发布 mail scope，或用户授权时未勾选 | 回第 2 步确认权限已发布，再让发信人重新登录 |
| 草稿创建成功但发送失败 | 公共邮箱未授权给该成员使用，或被企业邮件安全策略拦截 | 检查公共邮箱成员配置 / 企业邮箱安全设置 |
| 收件人收不到 | 收件人地址非企业邮箱或拼写错误 | 用 `send_notice` channel=mail 单发自己邮箱定位 |
| 想临时关闭邮件通道 | — | 删除 `MAIL_SENDER_OPEN_ID` secret 并 redeploy，即恢复 disabled 降级 |

## 回退

邮件通道是纯增量：删除 `MAIL_SENDER_OPEN_ID` secret + redeploy 即完全关闭，群机器人主通道不受任何影响；代码保留无运行成本。
