## 1. 背景

V1.0 方案定义的 MVP 已上线（`hub.newenergycoder.club`），门户四 Tab、MCP 部署链路、Skill 同步、MES 上架均跑通。2026-10-11 发布的对标文章展示了卡兹克中台的完整形态，对照后确认我方架构方向不变（数据在飞书、权限复用飞书、Agent 原生），但在**内容资产、数据智能、个性化、运营自动化**四个维度存在明确差距。本 PRD 将差距转化为可排期、可验收的产品需求。

## 2. 目标与成功指标

**产品目标**：队员用 AI 做出的任何应用/Skill/资料，3 分钟内完成上架、按权限被全队访问；中台成为战队唯一的数字入口。

| 指标 | 定义 | 目标值 | 测量方式 |
|---|---|---|---|
| 上架时长 | 从队员说"做好了"到应用广场可见 | ≤ 3 分钟 | MCP 日志时间戳 |
| 周活跃渗透 | 每周访问中台的队员数 / 全队人数 | ≥ 70% | Worker 访问日志（按飞书 user_id 去重） |
| 数据准确率 | 数据校验 Agent 扫描出的异常中，确认属实的比例 | 首轮 ≥ 80% | 异常清单人工复核 |
| 数据异常清零 | 4 张底表校验异常从首轮扫描到清零的耗时 | ≤ 2 周 | 校验报告时间线 |
| 赛季目标可见率 | 队员能在中台一句话说清本赛季剩余关键节点 | 问卷 ≥ 80% | 上线 2 周后飞书问卷 |
| 交接成本 | 新一届负责人接管中台全部资产所需时间 | ≤ 1 天 | 交接 README 走查 |

## 3. 用户与角色

权限复用飞书体系，角色取自"队员名单"多维表格，**不做自建账号体系**。

| 角色 | 来源 | 核心诉求 | 关键权限 |
|---|---|---|---|
| 队长 | 名单表 role=队长 | 赛季全景、审批待办、交接 | 全部读写 + 发布审核 |
| 组长（机械/电控/视觉/运营） | role=组长 | 本组任务进度、组内数据 | 本组数据读写 + 本组首页配置 |
| 队员 | role=队员 | 找应用、找资料、报任务、交报销 | 全员可见范围内读写 |
| 校友 / 指导老师 | role=校友，飞书组织外 | 只读了解战队动态 | 仅公开区（无登录态亦可看公开页） |

## 5. 功能需求

优先级：**P0 = 地基，阻塞其他需求；P1 = 高价值主力功能；P2 = 增强体验**。

### FE-01 飞书 OAuth 登录态与权限角色（P0）

**用户故事**：作为队员，我打开中台即识别我是谁，只看到我有权看的内容，不用二次登录。

**需求描述**：

- 在现有 `/auth/feishu` 回调基础上增加**会话保持**：签发 HttpOnly Cookie（Worker KV 存 session，7 天有效，滑动续期）。
- 新增 `whoami` API：返回当前登录用户的飞书 user_id、姓名、角色（实时查"队员名单"表）。
- 门户所有页面按角色渲染：未登录可见公开区（应用广场公开应用 + Skill 中心）；登录后解锁角色内容。
- MCP 调用支持携带用户 OAuth token（或 session），`query_bitable` 按角色过滤数据范围（队员只能查公开表；财务报销表仅队长/财务角色）。
- 登出入口；队员被移出飞书组织后会话自动失效（每次请求实时校验名单表）。

**验收标准**：

1. 飞书内打开中台免登（复用 MES 已验证的 JSAPI 路径）；浏览器打开走 OAuth 扫码，一次登录 7 天内免重复登录。
2. 用队长、组长、队员三个测试账号登录，看到的内容范围不同；队员账号访问财务报销表 API 返回 403。
3. 把测试队员从"队员名单"表移除后，其 session 下一次请求即失效。
4. 校友（无飞书组织身份）可匿名浏览公开区，访问任何角色接口返回 401 而非 500。

**进展（2026-10-14，主体已上线）**：

- ✅ 会话保持：KV `session:<sid>`，HttpOnly + SameSite=Lax，7 天有效，剩余不足一半时 sid 轮换滑动续期；登出接口销毁会话。
- ✅ `whoami` API + 角色判定：按"队员名单"表 open_id 精确匹配（姓名兜底），60s KV 缓存，负结果不缓存（退队即时失效）。
- ✅ 财务按角色脱敏：看板财务区 hidden（未登录）/summary（队员）/full（队长·财务）三级；MCP `query_bitable` finance 表需 `MCP_TOKEN` 或有效 user_token（角色为队长/财务）。
- 待办：飞书内 JSAPI 免登端到端验证（验收 1）、三角色测试账号走查（验收 2）、401/403 边界用例确认（验收 4）。

### FE-02 数据基建落地与看板接入（P0）

**用户故事**：作为组长，我打开中台数据看板，看到的是真实的任务进度和物资余量，不是占位符。

**需求描述**：

- 4 张多维表格真实建立并灌入当前赛季数据：队员名单 / 任务进度 / 物资台账 / 财务报销（字段定义按 V1.0 方案 §4.1）。
- 通过 `config_dashboard` 完成 base 与 table_id 配置，数据看板 `/api/dashboard` 展示：任务进度（按组分组、按状态统计）、物资余量 TOP 告警、本赛季报销概览（仅财务角色可见明细）。
- 看板数据加 5 分钟 KV 缓存（飞书免费版 API 频次限制）。

**验收标准**：

1. 4 张表在飞书内可打开，记录数 > 0，关键字段（负责人、状态、数量、金额）无空值。
2. `/api/dashboard` 返回的数据与多维表格当前值误差 ≤ 5 分钟。
3. 连续刷新看板 30 次不出现飞书 API 限流错误。
4. 财务概览对队员角色只显示汇总数字，不显示个人报销明细。

### FE-03 资料页（P1）——对标卡兹克"中台资料页"

**用户故事**：作为新队员/宣传组，队标怎么用、PPT 模板在哪、报销怎么走，在中台一个页面全找到，永远是最新版。

**需求描述**：

- 门户新增第 5 个 Tab"资料页"，内容分四类：
  - **品牌规范**：队标 VI（标准色值、最小尺寸、禁用示例）、宣传海报模板、视频片头/片尾模板；
  - **文档模板**：技术方案报告模板、答辩 PPT 模板、会议纪要模板；
  - **制度 SOP**：财务报销流程、仓库领用规范、换届交接清单；
  - **培训材料**：各组入门教程链接（飞书文档直链）。
- 内容载体：优先存飞书文档/云盘，资料页只存**索引 + 可见范围**（数据不下沉原则）；文件类模板（PPT/海报源文件）存 R2 或飞书云盘。
- 每条资料标注：维护人、最近更新、适用角色。
- 更新流程：任何人可通过 MCP `publish_doc`（新增工具，等价于 `publish_skill` 的资料版）提交更新，组长以上角色生效。

**验收标准**：

1. 每类资料 ≥ 3 条有效内容，无死链。
2. 新队员仅凭资料页可独立完成：下载队标、拿到答辩 PPT 模板、搞清报销流程（走查测试）。
3. 更新一条资料后，资料页 1 分钟内反映新版本并显示更新时间。

**进展（2026-10-14，资料页已上线）**：

- ✅ MCP `publish_doc` 工具上线（id/title/description/category/url/visibility/maintainer，KV `docs:registry` upsert，等价于 `publish_skill` 的资料版）。
- ✅ 门户"资料页" Tab + `/api/docs`（未登录仅见 visibility=all；已登录见全部），种子数据四类 10 条已写入。
- ✅ 门户内置"资料页更新 Prompt"生成器，队员复制给 Agent 即可发布/更新资料。
- 待办：占位链接（example.feishu.cn）替换为真实飞书文档并认领维护人（验收 1/2）、死链走查。

### FE-04 赛季目标可视化面板（P1）——对标卡兹克"OKR 面板"

**用户故事**：作为队长，一张图看完本赛季还剩哪些关键节点、哪组落后；作为队员，我清楚自己这周该盯什么。

**需求描述**：

- 新增多维表格"赛季目标"：字段 = 目标/关键结果/负责组/截止日期/完成度%/状态。
- 看板新增"赛季目标"区块：里程碑时间线 + 各组完成度横向条形图 + 逾期未达标红色告警。
- 完成度% 支持 MCP `update_progress` 回写（Agent 可直接更新）。
- 关键节点（如报名截止、中期检查、场地测试）T-7 天自动出现在门户顶部通知条。

**验收标准**：

1. 面板展示的每个目标可点击跳转多维表格原始行。
2. 完成度回写后，面板 ≤ 1 分钟刷新。
3. 创建一个截止日期为明天的测试目标，门户顶部出现告警条。

### FE-05 数据校验 Agent（P1）——对标卡兹克"Agent 扫出一千多条绑定错误"

**用户故事**：作为队长，Agent 定期帮我扫 4 张底表，把脏数据按类型列成清单，我照着清就行。

**需求描述**：

- 新增 MCP 工具 `validate_bitable(scope)`，内置规则集：
  - 队员名单：飞书 ID 为空/格式错、组别不在枚举值、角色字段缺失；
  - 任务进度：无负责人、截止日期早于创建日期、状态与完成度矛盾（100% 却未标完成）；
  - 物资台账：数量为负、领用人不在名单表、位置字段为空；
  - 财务报销：金额缺失、发票状态与流程矛盾。
- 输出"异常清单"：类型 / 所在表 / 记录链接 / 建议修复动作；门户新增"数据健康"入口展示，按类型分组。
- 校验可由队员对自己的数据触发，但**全量校验仅队长/组长**；支持 Cron Trigger 每周一自动跑并推送结果到队长（飞书群机器人 webhook）。
- 校验规则为声明式配置（JSON 存 KV），新增规则无需改代码。

**验收标准**：

1. 在测试表中预埋 10 条各类脏数据，校验全部命中且无误报 ≥ 80%。
2. 每条异常带多维表格记录直链，点开即可修。
3. 每周一 8:00 队长收到飞书群校验摘要（本周新增/已清零/持续异常数）。

### FE-06 千人千面"改我的首页"（P2）

**用户故事**：作为队员，我右下角点"改我的首页"，用一句话告诉 Agent 我想要什么，它生成并绑定到我的账号。

**需求描述**：

- 门户首页支持**模块化自定义**：用户可增删排布小组件（我的应用快捷区、我的任务、我的报销状态、常用资料）。
- "改我的首页"入口：输入自然语言需求 → 调用 Agent（走 MCP）生成布局配置 → 绑定飞书 user_id → 门户按用户配置渲染。
- 配置存 KV（`home:<user_id>`），提供"恢复默认"。

**验收标准**：

1. 用自然语言"把物资查询放到最上面，加我的未完成任务"执行后，重新登录布局保持。
2. 另一账号登录看到默认布局，互不影响。
3. "恢复默认"一键生效。

*依赖：FE-01。此功能即文章所说的"不会用 Agent 的同事寸步难行"的引导器，也是低代码实践的展示窗口。*

### FE-07 组别默认首页（P2）

**用户故事**：机械组打开中台默认看到机械的任务和物资，视觉组默认看到视觉的——不用自己翻。

**需求描述**：

- 新增"组首页"配置：组长可为本组配置默认布局（数据范围限本组）。
- 用户未自定义个人首页（FE-06）时，按所属组渲染组首页；两者都无时渲染全员默认首页。
- 优先级：个人配置 > 组配置 > 默认。

**验收标准**：

1. 两个组配置不同首页后，组员登录分别看到本组内容。
2. 用户做过个人定制后，组首页不再覆盖。
3. 未登录访客始终看到默认首页。

### FE-08 标杆应用：报销助手（P1）——对标卡兹克"商务助手 1 小时开发"

**用户故事**：作为队员，我上传发票照片，应用自动识别、校验报销材料齐不齐、生成待确认邮件草稿抄送队长，数据回写财务底表。

**需求描述**：

- 第一个端到端业务链路应用，作为"队员 Vibe Coding 标杆"示范（目标：1 小时开发、当天迭代）。
- 链路：上传发票 → OCR/手动录入金额事项 → 按报销 SOP（FE-03 资料页同一份）校验材料 → 生成确认邮件草稿（抄送队长+财务）→ 确认后回写"财务报销"表。
- 通过 `deploy_app` 上架应用广场，标注作者与可见范围。
- 输出一篇实战复盘文档（开发时长、Prompt 模板、踩坑），供其他队员复制该模式。

**验收标准**：

1. 完整链路走通一单真实（或测试）报销，财务表中出现对应记录，状态正确。
2. 非作者队员按权限可打开使用；校友不可见。
3. 复盘文档进入资料页"标杆案例"区。

**进展（2026-10-13，报销界面优化已上线门户数据看板）**：

- ✅ **报销时间**：财务报销聚合新增"报销时间/报销日期"字段提取（兼容日期字段与文本日期），看板"最近报销"按时间倒序展示日期与申请人。
- ✅ **上传单据识别**：报销表单支持上传单据（发票/收据图片或 PDF），图片经 Tesseract.js（chi_sim）本地 OCR 自动识别金额与日期并回填表单，可手动修改；识别全程在浏览器本地完成，不经第三方。
- ✅ **付款凭证识别**：独立的付款凭证上传位（微信/支付宝截图），同样自动识别金额。
- ✅ 提交链路：POST /api/reimburse（需登录）→ 凭证文件存档至 R2 receipts/ → 按字段名模糊匹配写回飞书"财务报销"表（按字段 ui_type 序列化日期/数字），并自动清看板缓存。
- 待办：材料齐不齐的 SOP 校验、确认邮件草稿、复盘文档。

### FE-09 审批/待办聚合（P2）

**用户故事**：作为队长，我打开中台就看到待我审批/待我处理的事，不用在飞书各应用间翻。

**需求描述**：

- 登录后门户顶部"待办条"：聚合飞书审批待办（通过飞书审批 API）、逾期未完成任务（来自任务表）、待处理的报销确认。

## 7. 技术方案要点（架构不变，仅增量）

```
队员 Agent ──MCP──▶ Worker（新增：session/whoami/publish_doc/config_drawing_review；待做：validate_bitable/update_progress）
                     │
门户（已上线：资料页 Tab / 图纸评审 Tab；待做：赛季目标区块 / 待办条 / 个人与组首页渲染）
                     │
飞书（既有 4 表接入校验规则集；新增表：赛季目标、图纸评审 10 表）── 群机器人 webhook（周一校验摘要）
```

- 会话：KV `session:<sid>` → `{user_id, expires}`，滑动续期 7 天。
- 角色：每请求实时查"队员名单"（带 60s KV 缓存），退队即失效。
- 校验规则集：KV `validate:rules`，声明式 JSON，新增规则零代码。
- 个性化：KV `home:<user_id>` / `home:group:<组名>` / `home:default` 三层回退。

## 10. 风险与边界

- **飞书免费版限制**：API 频次、定制工作台入口、审批能力可能受限 → 全部设计保留降级路径（缓存、Level 2 入口、Plan B 小组件方案），手册已记录。
- **FE-05 误报**：校验规则宁缺毋滥，首轮只上线 4 类表各 3-5 条高置信规则，误报率 > 30% 的规则下线重调。
- **FE-06 生成质量**：Agent 生成的首页可能破坏可读性 → 小组件白名单制，只许组合不许自由 HTML。
- **OCR 成本**：FE-08 发票识别优先调飞书/免费 OCR，识别不了降级为手动录入，不引入付费 API。
- **创始人依赖**：所有新功能的配置写入交接 README，作为每个需求验收的一部分（见 §6）。
- **范围纪律**：FE-06/07/09 为 P2，若 M2 后团队精力不足，允许整体顺延一个赛季，不影响中台主价值闭环。
