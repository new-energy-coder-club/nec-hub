# 「协议签署审批」飞书后台云端配置手册

> 配套文档：[PRD_协议签署OA审批_V1.0.md](PRD_协议签署OA审批_V1.0.md)
> 前置条件：操作人需为飞书企业**管理员**或具有审批应用管理权限的子管理员。
> 说明：飞书审批定义不支持 API 创建，必须按本手册在云端后台手动配置；配置完成后即可通过 API 发起提单。

---

## 第 1 步：进入审批管理后台

1. 浏览器打开飞书管理后台：`https://feishu.cn/admin`
2. 左侧导航选择 **工作台 → 审批**，或直接访问审批管理页
3. 点击右上角 **创建审批**

## 第 2 步：基础信息

| 配置项 | 填写值 |
|---|---|
| 审批名称 | 协议签署审批 |
| 审批图标 | 任选（建议合同/文件类图标） |
| 所在分组 | 法务合规（无该分组则先新建分组） |
| 审批说明 | 合作协议、保密协议签署前的法务/运营/合规联合审核 |
| 可见范围 | 全体成员（或按部门限定） |

## 第 3 步：表单设计（共 11 个控件）

在「表单设计」页，从左侧控件栏依次拖入并按右侧面板配置：

| # | 控件 | 控件名称 | 必填 | 关键配置 |
|---|---|---|---|---|
| 1 | 单选 | 协议类型 | 是 | 选项：① 合作协议 ② 保密协议（NDA） |
| 2 | 单行文本 | 合作方名称 | 是 | 提示语：对方公司/机构全称 |
| 3 | 单行文本 | 合作方统一社会信用代码 | 否 | 提示语：便于法务与合规核验主体资质 |
| 4 | 单行文本 | 协议主题 | 是 | 提示语：一句话概括合作/保密事项 |
| 5 | 日期区间 | 协议期限 | 是 | 起止日期格式 |
| 6 | 金额 | 涉及金额 | 否 | 币种默认 CNY |
| 7 | 单行文本 | 我方签署主体 | 是 | 可设默认值：默认签约公司全称 |
| 8 | 附件 | 协议文本附件 | 是 | 提示语：上传待审核的协议 Word/PDF |
| 9 | 附件 | 补充材料 | 否 | 资质证明、背景资料等 |
| 10 | 多行文本 | 事项说明 | 是 | 提示语：合作背景、紧急程度、特殊条款 |
| 11 | 日期 | 期望签署日期 | 否 | — |

## 第 4 步：流程设计（法务 → 运营 → 合规）

在「流程设计」页，在发起人节点后依次添加三个审批节点：

1. **节点 1：法务审核**
   - 审批人：指定成员（法务对接人）或按角色选择法务组成员
   - 多人时审批方式：**或签**
   - 节点名称改为「法务审核」
2. **节点 2：运营审核**
   - 审批人：运营负责人；方式：或签
3. **节点 3：合规审核（终审）**
   - 审批人：合规负责人；方式：或签
4. 每个节点点击 **高级设置 → 驳回时**：选择「驳回到发起人」
5. 在流程末尾添加 **抄送节点**：抄送人 = 发起人、印章管理员；触发时机 = 审批通过后

## 第 5 步：高级设置

| 配置项 | 建议值 |
|---|---|
| 允许发起人撤回 | 开启（协议文本变更场景需要） |
| 允许催办 | 开启 |
| 审批意见必填 | 驳回时必填（保证驳回原因可追溯） |
| 数据可见范围 | 默认（发起人 + 节点审批人 + 抄送人） |
| 打印/导出权限 | 仅审批管理员 |

## 第 6 步：发布与灰度验证

1. 点击右上角 **发布**，并设置可见范围生效
2. 记录发布后的 **approval_code**（在审批定义详情页 URL 或 API 查询中可见）
3. 灰度验证：用一个真实协议走完整流程，确认：
   - 三级节点按法务 → 运营 → 合规顺序流转
   - 驳回能正确退回发起人
   - 通过后发起人、印章管理员收到抄送
4. 验证通过后全员公告，废止线下流程

## 第 7 步：API 对接（配置完成后）

拿到 `approval_code` 后，可验证 API 提单链路：

```bash
# 查看定义详情（确认控件 ID 与节点配置）
lark-cli approval approvals get --params '{"approval_code":"<APPROVAL_CODE>"}' --as user

# 发起测试单据
lark-cli approval instances create --data '{"approval_code":"<APPROVAL_CODE>","form":"[...]"}' --as user --yes
```

## 配置检查清单

- [ ] 分组与名称正确，可见范围已生效
- [ ] 11 个表单控件齐全，必填项与 PRD 一致
- [ ] 三个审批节点顺序为法务 → 运营 → 合规
- [ ] 每个节点驳回策略为「驳回到发起人」
- [ ] 末尾抄送节点包含发起人和印章管理员
- [ ] 已发布并完成一单灰度验证
- [ ] 已记录 approval_code 并移交 API 对接
