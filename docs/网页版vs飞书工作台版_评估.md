# 网页版 vs 飞书应用工作台版 — 形态评估

> 配套文档：《团队AI中台搭建方案_V1.0.md》
> 结论先行：**两者不冲突，是同一套中台的两种入口**。代码只需一份，差异在"用户从哪里进来"。推荐：网页版为主体，飞书工作台版为入口增强。

---

## 1. 形态定义

| 形态 | 含义 |
|---|---|
| **网页版** | 队员直接访问 `hub.newenergycoder.club`，浏览器打开使用 |
| **飞书工作台版** | 在飞书管理后台把"工作台"入口配置为中台 URL，队员在飞书 App 内点工作台即进入中台（内嵌 WebView） |

参考文章（卡兹克）用的正是第二种，但前提是他们公司已经"长在飞书上"。我们团队要按实际情况权衡。

## 2. 对比评估

| 维度 | 网页版 | 飞书工作台版 |
|---|---|---|
| **触达路径** | 记域名/收藏书签，2 步 | 飞书 → 工作台，1 步，日常动线内 ✅ |
| **使用场景** | 桌面端开发时顺手 ✅ | 手机端飞书也能进（移动端友好）✅ |
| **配置门槛** | 零配置，部署即用 ✅ | 需飞书管理员后台配置工作台入口，且**自建应用/工作台自定义需要一定版本权限** ⚠️ |
| **登录态** | 需自己做 OAuth 跳转 | 飞书内免登（JSAPI 直接拿身份）✅ |
| **能力扩展** | 纯 Web 能力 | 可调飞书 JSAPI（消息推送、群机器人联动、审批跳转）✅ |
| **脱离飞书的兜底** | 飞书挂了照样能用 ✅ | 强绑定飞书生态 ⚠️ |
| **换届交接** | 只交接域名 + CF 账号 ✅ | 还要交接飞书管理后台配置 ⚠️ |
| **调试成本** | 普通浏览器 DevTools ✅ | 内嵌 WebView 调试麻烦（vConsole/真机）⚠️ |
| **外部访问** | 校友、指导老师可直接给链接 ✅ | 仅限飞书组织内成员 ⚠️ |

## 3. 关键判断（针对 NEC 竞赛团队）

1. **团队飞书使用深度决定上限**。目前团队的名单/报销/任务并未全部搬进飞书多维表格，"长在飞书上"的前提还不完全成立 —— 先把数据基建做了，工作台版才有意义。
2. **MVP 阶段网页版先行是对的**：零配置、调试方便、校友可访问，先把"应用广场 + MCP 部署"这个核心价值跑起来。
3. **飞书工作台版是入口增强而非新系统**：等数据进飞书后，只需一步管理后台配置，把同一个 URL 挂进去即可获得"免登 + 移动端触达"，边际成本极低。
4. **不要反过来做**（先工作台后网页）：WebView 调试和飞书权限申请会拖慢 MVP，且队员开发场景主要在桌面浏览器。

## 4. 推荐路线

```
阶段一（现在）   网页版 MVP          ← 已搭建完成（nec-hub）
     ↓
阶段二          数据进飞书（4 张多维表格 + 自建应用）
     ↓          中台加飞书 OAuth 登录（网页版也可用）
     ↓
阶段三          飞书工作台入口配置   ← 同一个 URL，零额外开发
              + JSAPI 免登 + 群机器人联动（报销/审批通知）
```

**一句话**：网页版是"本体"，飞书工作台版是"飞书里的快捷方式"。先把本体做扎实，入口随时可加。

## 5. 风险备注

- 飞书工作台自定义入口的可用性取决于团队飞书版本（免费版部分管理功能受限），配置前需管理员确认后台是否有"工作台管理"权限。
- 若未来飞书版本不满足，平替方案：飞书群机器人每日推送中台链接 / 把中台加为飞书"常用应用"快捷方式，体验损失可接受。
