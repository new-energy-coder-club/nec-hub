## 1. 灰度目标与范围

### 1.1 灰度目标

按 PRD §16.3 灰度策略，先以 **1 个真实新增机项目** 跑通全链路，验证流程可用性与数据准确性，试点复盘通过后再向全部新增机项目推广。

### 1.2 灰度范围（试点全链路）

```
提交图纸报告书 → 会议预约 → 会议纪要/评审结论 → BOM 生成
      → 库存导入（手动兜底）→ 询价单生成 → 报价回填/比价/选定
      → 流程看板跟踪 → 事件日志审计
```

| 维度 | 范围 |
|------|------|
| 试点项目 | 1 个真实新增机项目（由项目经理指定） |
| 开放对象 | 仅该项目组成员（设计负责人、评审专家、电控/布线负责人、采购代表、生产负责人、项目经理） |
| 使用入口 | 门户「图纸评审」Tab（`hub.newenergycoder.club`）与独立应用页（`/apps/drawing-review/`）双入口，共用同一套 `/api/drawing-review/*` 后端与同一份飞书多维表格数据 |
| 灰度周期 | 建议 2 周（对齐 PRD §8「上线试运行」），以全链路走完一次为准 |

### 1.3 兜底原则（PRD §16.3）

试点期间 **腾讯会议 / ERP / MES 未联调的环节用手动导入模板兜底，不阻塞主流程**：

| 环节 | 正式路径 | 兜底路径 |
|------|----------|----------|
| 会议预约 | 腾讯会议 OpenAPI 自动预约 | mock/人工在腾讯会议建会后，将会议 ID/链接人工补录进评审单 |
| 库存与 MES 位置 | ERP/WMS/MES 接口自动拉取 | 使用手动导入模板，经 `POST /{id}/inventory/import` 上传库存快照，系统按同一口径展示并标注来源为「手动导入」 |

## 3. 全链路验证步骤表

按顺序执行，每一步记录结果到第 7 章签到表。「验收条款」对应 PRD §13 编号；标注 **【兜底路径】** 的步骤为腾讯会议/ERP/MES 未联调环节的替代走法，兜底通过视同正式通过。

| # | 步骤 | 操作（API / 页面） | 预期结果 | 验收条款 |
|---|------|-------------------|----------|----------|
| 1 | 打开提交表单并检查默认值 | 门户 → 图纸评审 → 新建提交；或 `GET /api/drawing-review/start` | 版本号自动推荐下一版本（已有 V1.0 则推荐 V1.1）；设计负责人默认为当前登录用户 | §13.1-2 |
| 2 | 提交图纸报告书 | 页面提交；或 `POST /api/drawing-review/submit`（projectId / machineName / drawingFiles 等） | 5 秒内生成 `DR-` 前缀唯一编号评审单，状态 `pending_review`；事件日志表新增 `submit` 记录 | §13.1-1、§13.1-4 |
| 3 | 校验必填字段拦截 | `POST /submit` 缺项目编号/机型名称/图纸文件 | 返回 400 并指明缺失字段，不产生评审单 | §13.1-3 |
| 4 | 会议预约 **【兜底路径】** | 正式：`POST /{id}/meeting`；兜底：人工在腾讯会议建会，将会议 ID/链接补录进评审单 | 会议主题「新增机图纸评审 - {机型} - {版本}」；会议信息写回评审单；API 失败时评审单状态不被破坏、事件日志记录失败原因、允许人工补录 | §13.2-1、§13.2-4 |
| 5 | 保存会议纪要 | `POST /{id}/minutes`（按纪要模板：议题/讨论记录/问题清单/下一步动作） | 纪要与当前图纸版本绑定，评审详情可回看 | §13.3-1 |
| 6 | 保存评审结论（通过路径） | `POST /{id}/conclusion`，结论 = 通过 | 状态机流转至 BOM 生成前序节点 | §13.3 |
| 6b | 保存评审结论（不通过路径，抽查） | `POST /{id}/conclusion`，结论 = 不通过 | 状态退回 `draft` 并记录退回原因，禁止进入下游 | §13.3-2 |
| 6c | 保存评审结论（有条件通过路径，抽查） | 结论 = 有条件通过 + ≥1 条整改项 → 整改完成后 `POST /{id}/rectify` | 状态置 `rectifying`；整改完成事件触发后自动流转至 BOM 生成 | §13.3-3 |
| 7 | 生成 BOM | `POST /{id}/bom/generate`（items 至少一项物料）；`GET /{id}/bom` 核对 | 10 秒内生成 L1-L4 层级 BOM，状态流转 `assessing`；缺必填字段的条目标记待补全 | §13.4-1、§13.4-2 |
| 8 | 机械加工件 BOM 核对 | `GET /{id}/bom/machining` | 仅筛选来源「自制」且工艺为机加/钣金/焊接的物料 | §13.10-1 |
| 9 | 库存导入 **【兜底路径】** | 按第 4 章模板准备数据，`POST /{id}/inventory/import` 上传；`GET /{id}/bom` 或看板核对 | 每条物料按物料编码命中 库存充足/不足/无库存/在制 四态之一，标注来源「手动导入」，命中项记录仓库/库位信息 | §13.7-1、§13.7-2、§13.7-3 |
| 10 | 生成询价单 | `POST /{id}/inquiries/generate`（幂等） | BOM 中库存不足的外购/标准件每个物料推荐 3 家供应商并生成询价单号；`GET /{id}/inquiries` 可查 | §13.11-1 |
| 11 | 报价回填 | `POST /api/drawing-review/inquiries/{inquiryId}/quote`（任意登录用户，模拟供应商） | ≥1 家报价回填成功，询价单状态更新 | §13.11-2 |
| 12 | 比价与选定供应商 | `POST /{id}/inquiries/compare`（`selections` 选定；仅队长/采购/项目经理） | 生成比价建议书；非授权角色选定返回 403 | §13.11-2 |
| 13 | 看板跟踪 | 门户图纸评审 Tab 看板；或 `GET /api/drawing-review/board` | 按状态正确分桶且与多维表格一致；「我的待办」准确；阻塞预警区可见 | §13.12-1、§13.12-2、§13.12-3 |
| 14 | 事件日志审计 | 打开事件日志表（`events`），核对本评审单全链路记录 | 提交/预约/纪要/结论/BOM/导入/询价/比价等关键操作均有留痕（操作人、时间、前后状态） | §13.1-4、PRD §18.3 |

## 4. 库存手动导入模板（兜底路径）

对应接口：`POST /api/drawing-review/{id}/inventory/import`（灰度期 ERP/MES 未联调时的库存数据入口，PRD §13.7-2）。

### 4.1 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 物料编码 | 文本 | 是 | 与 BOM 物料编码一致，作为匹配键 |
| 物料名称 | 文本 | 是 | 中文名称 |
| 规格型号 | 文本 | 否 | 规格参数 |
| 数量 | 数字 | 是 | 当前库存数量，≥0 |
| 单位 | 文本 | 是 | 件/套/米/公斤 |
| 仓库 | 文本 | 否 | 所在仓库名称 |
| 库位 | 文本 | 否 | 仓库内库位/MES 工位 |
| 数据来源 | 文本 | 自动 | 导入后系统自动标注为「手动导入」 |

### 4.2 JSON 示例（接口请求体）

```bash
curl -s -X POST https://hub.newenergycoder.club/api/drawing-review/DR-20261015-001/inventory/import \
  -H "content-type: application/json" \
  -b "nec_session=<登录会话>" \
  -d '{
    "items": [
      {
        "物料编码": "MAT-6014-001",
        "物料名称": "直线导轨 HGR20",
        "规格型号": "HGR20R1000C",
        "数量": 4,
        "单位": "件",
        "仓库": "总装库",
        "库位": "A-01-03"
      },
      {
        "物料编码": "MAT-6014-002",
        "物料名称": "步进电机",
        "规格型号": "57HS76-3004",
        "数量": 0,
        "单位": "件",
        "仓库": "总装库",
        "库位": "B-02-01"
      }
    ]
  }'
```

### 4.3 CSV 模板（先在表格工具中整理，再转 JSON 提交）

```csv
物料编码,物料名称,规格型号,数量,单位,仓库,库位
MAT-6014-001,直线导轨 HGR20,HGR20R1000C,4,件,总装库,A-01-03
MAT-6014-002,步进电机,57HS76-3004,0,件,总装库,B-02-01
MAT-6014-003,拖链,内高25×R55,2,米,线束库,C-05-02
```

### 4.4 导入注意事项

- 数量 = 0 的物料将判为「无库存」，进入询价筛选范围；
- 物料编码与 BOM 不一致的行无法命中，导入后需在 BOM 视图逐条核对未命中项；
- 同一评审单可重复导入，以最新一次快照为准；
- ERP/MES 接口就绪后，同一看板口径自动切换为接口数据，手动导入数据保留为历史快照（PRD §17.2 FAQ-5）。

## 5. 灰度验收通过与回退判据

### 5.1 通过判据

**全部满足**以下条件视为灰度通过，可向全部新增机项目推广：

1. PRD §13 验收标准（13.1–13.12）逐条走查通过；**走兜底路径的环节（§13.2 会议预约、§13.7 库存拉取）视同通过**，但须在复盘记录中注明「兜底通过」；
2. 试点项目全链路（第 3 章步骤 1–14）一次性走完，无阻断性缺陷；
3. 事件日志表审计完整，所有状态流转可追溯到操作人与时间；
4. 看板状态与多维表格数据一致（§13.12-1）。

### 5.2 回退判据（PRD §16.4）

出现以下任一情况，触发回退并记录原因：

- 代码级故障导致主流程不可用 → **代码回滚**：Worker 按版本保留，经 wrangler 版本回滚至上一版本，5 分钟内完成；
- 需整体下线入口 → **功能开关**：门户图纸评审 Tab 通过注册表配置下线（门户恢复六 Tab），数据仍保留在飞书多维表格，恢复入口即恢复使用；
- 回退不删除任何已产生的业务数据，飞书多维表格中的评审单/纪要/BOM/询价记录全部保留。

## 6. 问题记录与升级渠道

### 6.1 排查入口：事件日志表

所有状态流转与关键操作写入「事件日志」表（`events`），是排障第一入口（PRD §16.5、§18.3）：

1. 先在事件日志表中按评审单号过滤，确认最后一次流转事件与失败原因；
2. 看板状态与多维表格不一致时，先刷新页面，持续不一致则查事件日志确认最后流转事件（FAQ-6）；
3. 会议未自动约上时，查事件日志中的预约失败原因（常见为 API 权限不足），随后走人工补录兜底（FAQ-2）。

### 6.2 问题记录格式

在试点项目专项话题（飞书群）中按以下格式上报：

```
【灰度问题】评审单号：DR-XXXXXXXX-XXX
步骤：第 3 章步骤 N（步骤名）
现象：...
预期（验收条款 §13.x）：...
事件日志最后记录：...
临时处置：已走兜底路径 / 阻塞中
```

### 6.3 升级渠道

| 级别 | 场景 | 渠道 |
|------|------|------|
| L1 一般问题 | 操作疑问、字段不会填 | 战队飞书群「图纸评审流程专项话题」，工作日响应（PRD §17.3）；常见问题先查 PRD §17.2 FAQ |
| L2 流程问题 | 状态流转异常、权限不对、数据不一致 | 项目经理汇总 → 系统管理员排查（事件日志 + 多维表格直查） |
| L3 系统故障 | 接口 500、主流程阻断、数据丢失风险 | 系统管理员直接处理，必要时按 §5.2 触发回退 |
| 配置类问题 | 表结构、字段映射、table_id 缺失 | 系统管理员处理（PRD §17.3） |
