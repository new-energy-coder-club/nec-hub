## 1. 背景与定位

### 1.1 问题

队长与队员的待处理事项散落在飞书审批中心、任务进度表、财务报销表、四条本地审批底表（报销/图纸/硬件/合规）中，需要在飞书多个应用间来回翻找。V2.0 FE-09 只写了一句话需求，A-01 做了详细化，G-04 补了本地底表聚合与 T-1 标红——三份文档口径分散，本 PRD 收敛为待办能力的唯一权威文档。

### 1.2 产品目标

任何角色登录中台门户后 **10 秒内**看到自己全部待办（待审批 / 逾期任务 / 待确认报销），点开即跳转到处理页面，全程零人工传话。

### 1.3 成功指标

| 指标 | 口径 | 目标 | 测量方式 |
|---|---|---|---|
| 待办准确性 | 待办条计数与各源实际待办数一致 | 100%（≤5 分钟缓存窗口） | 验收用例 §8.1 |
| 聚合可用性 | 任一数据源失败时其余源正常返回 | 单源故障不白屏、不 500 | 故障注入用例 §8.2 |
| 角色隔离 | 队员不可见他人审批单/报销 | 0 泄漏 | 双账号对照用例 §8.1-2 |
| T-1 标红准确率 | 合规临期单标红无漏标误标 | 100% | 用例 §8.1-3 |
| 接口响应 | 命中缓存时 P95 | ≤ 200ms | 生产观察 |

## 4. 功能详述

### 4.1 T-01 四类数据源聚合【P0，已上线】

**用户故事**：作为队长，我打开中台就看到待我审批/待我处理的事，不用在飞书各应用间翻。

**聚合规则**（实现于 `src/todos.ts` `buildTodos`）：

| # | 类别 | 数据源 | 过滤规则 | 跳转目标 |
|---|---|---|---|---|
| ① | `tasks` 逾期任务 | 任务进度表（`fetchTableCached`） | 负责人=当前用户（多值字段按分隔符拆分精确比对）且 截止<今天 00:00 且 状态不匹配完成态正则（`完成/已完/完结/done/取消/关闭` 等） | 多维表格记录直链（`buildRecordLink`） |
| ② | `finance` 财务报销 | 财务报销表 | 状态匹配待处理正则（`待确认/待审核/待审批/待处理/进行中/审批中/提交`）；队长/财务见全部（`scope:"all"`），队员仅见自己（`scope:"mine"`） | 多维表格记录直链 |
| ③ | `approvals` 飞书审批 | `POST /open-apis/approval/v4/instances/search`（tenant token，`user_id=当前用户 open_id`，`status=PENDING`） | scope 未开通/报错 → 静默降级，仅在 `warnings` 说明 | `https://www.feishu.cn/approval/instance/<code>` |
| ④ | `approvals_local` 本地审批底表 | 4 张流程底表（`fetchFlowRecordsCached`，复用 `todo:tbl:<type>` 5 分钟缓存） | 状态="审批中"；审批人见全部，队员仅见自己提交（open_id 匹配，无 open_id 字段时兜底姓名匹配） | 底表记录直链 |

**排序**：`approvals_local` 内 urgent 置顶，其余按 deadline 升序（无 deadline 排最后）；`tasks` 按截止升序。前端将本地审批单区块整体排在待办清单最前（先于任务/报销/飞书审批）。

**截断**：`approvals_local` 与 `finance` 各取前 20 条；飞书审批 API `page_size=20`。

### 4.2 T-03 合规 T-1 标红【P1，代码已交付待复核】

**用户故事**：作为合规审批人，我希望"明天要发布但还在审批中"的推文一眼可见，避免延误发布窗口。

**判定规则**（`src/todos.ts` `T1_URGENT_MS = 24h`）：

```jsonc
{
  "application_id": "CP-2026-0007",
  "title": "CP-2026-0007 招新推文发布",
  "url": "<底表记录链接>",
  "type": "compliance",
  "deadline": 1760313600000,   // 仅 compliance：计划发布时间（fieldTs），其他流程为 null
  "urgent": true               // type=compliance 且 deadline - now ≤ 24h（含已过点）且仍审批中
}
```

**前端渲染口径**：

- `urgent=true`：红色高亮 +「T-1」徽标，区块内自然靠前（不另设组内排序）；
- 非 urgent 且有 deadline：显示「距计划发布还有 X 天」（`Math.ceil` 向上取整）；
- deadline 已过点：显示「已过计划发布时间」；
- 仅 compliance 流程有 deadline（字段模糊匹配 `计划发布时间/发布时间`），其余流程该项为 null。

### 4.3 T-04 缓存与降级策略【P0】

- **用户级缓存**：KV `todos:<open_id>`，TTL 300 秒，命中返回 `cached:true`；写缓存走 `ctx.waitUntil` 不阻塞响应。
- **表级缓存复用**：本地审批底表复用 `todo:tbl:<type>` 5 分钟缓存（与 SLA 巡检共用，防飞书 API 限流）；任务/财务表复用 `fetchTableCached`。
- **三级降级**（任何一级失败不拖垮整体）：
  1. 飞书审批 API 失败/未配置 → `warnings` 说明，退化为任务+报销+本地审批聚合；
  2. 单表读取失败 → 该表计 0 条 + warning，其余正常；
  3. 聚合整体异常 → 返回 `total:0` + warnings 的合法 payload（HTTP 200），前端待办条自动隐藏，**永不 500/白屏**。

### 4.4 T-02 门户待办条 UI【P0，已上线】

- 位置：门户顶部 `#todo-bar`（所有 Tab 可见），与 FE-04 `#goal-banner` 提醒条并存互不干扰；
- 未登录或 `total=0` → 整条不渲染；
- 显示合计计数徽标 + 可展开清单（按四类分组：本地审批 / 任务 / 报销 / 飞书审批），每条含标题、状态/倒计时、跳转链接；
- 角标数字与下拉列表同源（同一次 `/api/todos` 响应），禁止两处各查；
- 移动端窄屏下红标不溢出（跟随门户移动端适配基线）。

### 4.5 T-06 MCP `list_todos`【P2，已上线】

- 签名：`list_todos(open_id)` → 拉取指定用户待办，聚合结果按 type 分组返回；
- 供 Agent 场景使用（"我今天有什么待办"），与门户共用 `buildTodos` 同源数据，无第二份过滤逻辑。

## 5. 接口契约

### `GET /api/todos`（需登录）

未登录返回 `401 { "error": "请先登录" }`。成功响应：

```jsonc
{
  "generatedAt": "2026-10-15T03:00:00.000Z",
  "cached": false,                 // true = 命中 5 分钟缓存
  "total": 7,                      // 四类之和
  "tasks": [ { "title": "...", "owner": "...", "status": "进行中",
               "deadline": 1760054400000, "daysOverdue": 3, "link": "..." } ],
  "finance": { "count": 2, "scope": "all",     // mine | all
               "items": [ { "name": "...", "amount": 128.5, "applicant": "...",
                            "status": "待确认", "link": "..." } ] },
  "approvals": { "count": 0, "items": [ { "title": "审批实例 xxx", "link": "..." } ] },
  "approvals_local": { "count": 4,
               "items": [ { "application_id": "CP-2026-0007", "title": "...",
                            "url": "...", "type": "compliance",
                            "deadline": 1760313600000, "urgent": true } ] },
  "warnings": [ "飞书审批待办不可用（审批 API scope 未开通或未授权），已降级为任务/报销聚合：..." ]
}
```

约束：`warnings` 非空时 HTTP 状态仍为 200；`total` 必须等于四类计数之和；所有 `link/url` 必须可直接点击跳转。

## 7. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 飞书审批 scope 持续未开通 | 类别 ③ 长期降级，双通道变单通道 | 类别 ④ 本地聚合即是兜底，不阻塞；开通后自动生效无需发版 |
| 底表字段名被手工改乱 | 模糊匹配失败，该流程待办静默为 0 | `findFieldKey` 多正则兜底；建议配合 `config_validate_rules` 校准真实表字段名 |
| 队员姓名重名 | 兜底姓名匹配可能误配 | 优先 open_id 匹配；名单表推动补录 open_id |
| 5 分钟缓存窗口内状态滞后 | 用户处理完待办后数字未立即减少 | 文档注明缓存窗口；验收标准允许 ≤5 分钟延迟 |
