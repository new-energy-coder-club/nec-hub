# NEC 战队 AI 中台搭建方案 V1.0

> 参考：数字生命卡兹克《我们用 2 天，给公司做了一个 AI 中台》
> 适用对象：常州工学院 NEC 战队 / ROBOCON 竞赛团队（约 20–40 人，跨机械、电控、视觉、运营、宣传组）
> 文档日期：2026-10-10

---

## 1. 背景与痛点

参考文章中，卡兹克的公司（30 余人）全员 Vibe Coding，但遇到四个典型痛点。映射到我们竞赛团队，几乎一模一样：

| 参考文章中的痛点 | 我们团队的对应现状 |
|---|---|
| 同事各自 Vibe Coding 小工具，但**部署难** | 队员用 Claude/Kimi/Codex 写了报名统计、物资盘点、工时统计等小工具，只在自己电脑上跑 |
| 做出来的东西**别人不知道、没法分享** | 工具散落各处，换届后直接失传 |
| **权限管理**缺失 | 队员名单、财务报销等数据不便全员公开，但没有细粒度管控手段 |
| 各种 Skill / 提示词**协同分发困难** | 各组自己攒提示词，A 组调教好的"技术报告润色 Skill"，B 组根本不知道 |

**核心结论（与原文一致）**：我们需要的不只是一个分享页面，而是一个**以 Agent 操作为原生、以飞书数据为基建的团队 AI 中台**。

## 2. 目标与原则

**目标**：队员用 AI 做出的任何应用/Skill，3 分钟内完成上架、可被全队按权限访问。

**原则**：

1. **学生团队零成本优先**：全部建立在 Cloudflare 免费额度 + 飞书免费版 + GitHub 上，不租 VPS（可选增强项除外）。
2. **Agent 原生**：所有操作（部署、上架、查数据）都可以通过 MCP / Prompt 完成，不依赖人工点网页后台。
3. **权限复用飞书**：不自建账号体系，飞书 OAuth 登录，权限组 = 飞书部门/用户组。
4. **数据不下沉**：队员名单、任务进度、物资台账仍存飞书多维表格，中台只做"组织和呈现层"，换届交接零迁移成本。

## 4. 模块设计

### 4.1 数据基建层（飞书）

先把团队数据规范化，全部搬进多维表格，这是中台的地基：

| 多维表格 | 关键字段 | 典型消费者 |
|---|---|---|
| 队员名单 | 姓名/组别/赛季/飞书ID/权限角色 | 中台权限判定 |
| 任务进度 | 任务/负责人/截止/状态/关联文档 | 中台数据看板 |
| 物资台账 | 物料/数量/位置/领用人 | 物资查询应用 |
| 财务报销 | 事项/金额/发票状态/报销人 | 报销查询应用 |

> 前置动作：飞书开放平台创建一个**企业自建应用**，拿到 `app_id` / `app_secret`，开通多维表格读写、OAuth 登录权限。

### 4.2 中台门户（前端）

- 技术栈：静态站点（Astro/Vite + Tailwind），部署 Cloudflare Pages，域名 `hub.newenergycoder.club`。
- 四个 Tab：
  1. **应用广场**：卡片列表（名称/作者/截图/权限范围/入口链接），数据来自一个 `apps.json` 注册表（存 GitHub 仓库或 D1/KV）。
  2. **Skill 中心**：SKILL.md 列表 + 一键复制安装 Prompt。
  3. **数据看板**：调飞书多维表格 API 渲染任务进度、物资余量。
  4. **我的 Agent**：展示已接入 MCP 的 Agent 及接入 Prompt。
- **飞书工作台入口**：飞书管理后台支持将工作台入口配置为自定义网页 URL，队员进飞书点"工作台"直达中台（原文验证过的冷知识，直接复用）。
- 认证：飞书 OAuth 扫码登录 → 后端 Workers 校验 token → 按"队员名单"表的权限角色渲染可见内容。

### 4.3 团队 MCP Server（核心）

一个 Cloudflare Worker 实现的 MCP server，提供三类工具：

```
nec-hub-mcp
├── deploy_app(repo_path, name, visibility)   # 部署应用到 Pages + 注册到应用广场
├── publish_skill(skill_md_path, tags)        # 上架 Skill 到 Skill 中心
└── query_bitable(table, filter)              # 只读查询飞书多维表格（带权限校验）
```

**接入方式（抄原文的关键体验）**：中台"我的 Agent"页面给每个队员生成一段 Prompt，队员把它粘贴给自己的 Claude/Kimi/Codex，Agent 自动完成 MCP 安装与飞书 OAuth 绑定。示例：

```
请帮我接入 NEC 团队中台：
1. 安装 MCP server：https://hub.newenergycoder.club/mcp （streamable-http 传输）
2. 引导我完成飞书 OAuth 授权（打开返回的链接登录）
3. 完成后调用 nec-hub-mcp 的 whoami 验证，并告诉我已接入
```

**权限模型**：MCP 请求携带飞书 OAuth token → Worker 解析飞书 user_id → 查"队员名单"表得角色（队长/组长/队员/校友只读）→ 决定可部署/可见范围。

### 4.4 应用部署规范

队员 Vibe Coding 的应用大多是纯静态页或小工具，部署流程：

1. 队员在项目文件夹里粘贴"上架 Prompt"（从应用广场页复制）；
2. Agent 调 `deploy_app`：MCP 把构建产物推到 Pages 项目 `nec-apps`，路径 `/apps/<app-name>/`；
3. 自动写入注册表（名称、作者飞书ID、可见组别、版本、时间）；
4. 返回访问链接 `https://hub.newenergycoder.club/apps/<app-name>/`，权限校验在门户层统一做。

命名规范：`app-name` 小写连字符，如 `invoice-helper`、`inventory-check`；带后端逻辑的应用单独部署为 Worker，子路径 `/api/<app-name>/`。

### 4.5 Skill 中心

- 仓库：GitHub 私有仓库 `nec-skills`，每个 Skill 一个目录（`SKILL.md` + 脚本），CI 校验 frontmatter。
- 上架：`publish_skill` 把本地 SKILL.md 提交到仓库并更新索引。
- 分发：Skill 中心页面为每个 Skill 生成安装 Prompt，队员粘贴给自己的 Agent 即完成安装到 `~/.kimi/skills/` 或 `~/.claude/skills/`。
- 首批建议沉淀的团队 Skill：
  - `nec-tech-report`：ROBOCON 技术方案报告模板与润色
  - `nec-reimburse`：报销材料检查（对齐财务清算流程）
  - `nec-r2-sync`：图片传 R2 CDN（已有，直接迁入）

### 4.6 域名与规范

| 用途 | 域名/路径 |
|---|---|
| 中台门户 | `hub.newenergycoder.club` |
| MCP 端点 | `hub.newenergycoder.club/mcp` |
| 应用 | `hub.newenergycoder.club/apps/<name>/` |
| 图床 | `cdn.newenergycoder.club`（沿用现有 R2） |

## 5. 技术选型与成本

| 组件 | 选型 | 成本 |
|---|---|---|
| 门户前端 | Astro/Vite + Tailwind → Cloudflare Pages | 免费 |
| MCP Server / API | Cloudflare Workers | 免费额度（10 万请求/天）足够 |
| 注册表/会话 | Workers KV 或 D1 | 免费额度 |
| 数据层 | 飞书多维表格 + 开放平台自建应用 | 免费 |
| 认证 | 飞书 OAuth | 免费 |
| 代码托管 | GitHub 私有仓库 + Actions CI | 免费 |
| 图床 | Cloudflare R2（现有） | 现有 |

**可选增强**：若后续需要跑带状态的服务（如 WebSocket 计分系统），再考虑一台低配 VPS + Caddy 自动子域名（即原文方案），作为运行层的第二通道。

## 6. 实施路线

**MVP（一个周末，对标原文"2 天"）**

- Day 1 上午：飞书自建应用 + 4 张多维表格规范化；门户静态骨架（四个 Tab 空壳）上线 Pages。
- Day 1 下午：Workers 实现飞书 OAuth 登录 + 权限角色判定。
- Day 2 上午：MCP server 实现 `deploy_app` + 应用注册表；应用广场渲染。
- Day 2 下午：接入 Prompt / 上架 Prompt 模板；拿 1 个真实工具（如物资盘点）全流程跑通。

**第二阶段（1 周）**：Skill 中心 + GitHub CI；数据看板接多维表格；飞书工作台入口配置。

**第三阶段（按需）**：换届交接文档模板、权限组细化、可选 VPS 运行层。

## 8. 风险与边界

- **飞书免费版 API 频次限制**：看板类接口加 KV 缓存（5 分钟级），避免打满配额。
- **Pages 部署权限**：MCP 部署走 Cloudflare API Token，按队员角色限制可覆盖的 app 路径，防止误删他人应用。
- **数据安全**：中台不复制飞书数据，只做实时读取 + 短期缓存；队员退队 = 飞书移除，权限自动失效。
- **可持续性**：所有配置（域名、API Token、飞书应用）写进交接 README，避免"创始人依赖"——这也是对学生团队最重要的一条。
