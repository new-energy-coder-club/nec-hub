# 多维表数据规范与集成要求 — 各组组长维护手册

> 面向对象：各组组长（机械 / 电控 / 运营等）
> 目标：让你维护的飞书多维表格，能被 NEC 工作台首页（我的任务 / 赛季目标 / 物资 / 报销）**正确识别、正确排序、正确告警**。
> 管理员侧的建应用、配权限、写 `config_dashboard` 等步骤见 `docs/数据看板配置手册.md`，本文不重复。

---

## 一、工作台怎么读你的表（先理解，再维护）

1. 工作台每 30 分钟通过飞书机器人（企业自建应用）自动拉取一次表数据（KV 缓存，整表读取）。
2. **字段不是按固定列名读的，是按"候选关键词"模糊匹配的**（如列名含"截止"即识别为截止日期）。列名起得离谱（如"DDL""时间节点"）会匹配失败，页面上该列显示"—"，对应功能静默失效。
3. 匹配只采样前 50 条记录做嗅探：新加的列如果前 50 行全空，可能识别不到——**新列建好后先在已有行填一个值**。
4. 改表后最长 30 分钟生效；立即生效：工作台地址后加 `?fresh=1` 强制刷新，或等下一次 Cron 预热。

## 二、通用规则（两张表都适用）

### 2.1 字段类型是硬要求（最常见的坑）

| 用途 | 必须用的字段类型 | 用了文本会发生什么 |
|---|---|---|
| 截止日期 / 日期类 | **「日期」字段类型** | 任务表的逾期判断按数字解析，文本"2026-10-19"只会读出"2026"，**逾期标红、置顶排序全部失效**——这就是首页任务全部显示"—"、没有逾期提醒的根因 |
| 完成度 | 「数字」或「进度」字段 | 0~1 的小数会自动 ×100（飞书进度字段返回小数），0.6 = 60%；文本"60%"可解析，但纯文本"六成"不行 |
| 状态 / 优先级 / 层级 | 推荐「单选」 | 单选取值稳定，不会有人写"已完成 "（带空格）导致判定失效 |
| 负责人 | 「人员」或「文本」均可 | 人员字段取姓名，文本字段原样展示 |
| 金额 / 数量 | 「数字」 | 文本金额"1,200元"可解析，但"一千二"不行 |

### 2.2 状态词口径（系统内置，改不了）

- **任务"已完成"判定**：状态文本含 `完成 / 已完 / 完结 / done / 取消 / cancel / 关闭 / close / drop` 之一即视为完结，不计入"未完成"、不参与逾期统计。
  - 推荐单选值：`未开始 / 进行中 / 已完成 / 已取消`。
  - ⚠️ `搁置` `暂停` `待排期` 都**不算**完结，会被当作未完成并参与逾期统计——确实不做的任务请改成"已取消"。
- **目标"已达标"判定**：状态含 `完成 / 达成 / 达标 / done / close`，或完成度 = 100，即视为达标，不再告警。

### 2.3 排序与展示口径

- 首页"我的任务"最多展示 8 条，排序：**逾期置顶 → P0→P2 → 截止日近的在前**。
- 目标区按截止日升序；风险色 = 时间基准（年初 0% → 截止日 100%）与实际完成度的差距：**落后超 20% 标红、超 10% 标黄**。所以目标表**截止日期必须填**，否则时间基准算不出来，风险判断失效。

## 三、任务表（tasks）字段规范

推荐建在同一份多维表格的一个数据表里，列名按下表"推荐列名"起最省事（识别别名也能命中，但推荐列名优先级最高、零歧义）：

| 推荐列名 | 识别别名（列名含任一即命中） | 字段类型 | 取值建议 | 不填的后果 |
|---|---|---|---|---|
| **任务** | 任务标题 / 事项 / 标题 / title | 文本 | 一句话说清交付物 | 取首列文本兜底，标题可能不对 |
| **状态** | 进度 / status | 单选 | `未开始 / 进行中 / 已完成 / 已取消` | 视为"未标注"，且**不计入未完成**（状态为空的行连逾期都不算） |
| **负责人** | 执行人 / owner / assignee | 人员 | 一个人一行负责到底 | 首页负责人列显示"—" |
| **截止日期** | 截止时间 / deadline / 完成时间 / 日期 | **日期** | 见 §2.1，必须是日期类型 | 逾期置顶、红字、逾期计数全部失效 |
| **优先级** | priority | 单选 | `P0 / P1 / P2`（全大写） | 排序退化为同级 |
| **层级** | 级别 / 类型 / 分类 / level | 单选 | `Epic / Story` | Epic/Story 混在一起，看不出归属 |

> Epic/Story 建议结构：一个 Epic 一行，其下 Story 也各占一行，靠"层级"列区分（缩进展示由前端处理）；不要为 Story 建独立的列。

## 四、赛季目标表（goals）字段规范

| 推荐列名 | 识别别名 | 字段类型 | 取值建议 | 不填的后果 |
|---|---|---|---|---|
| **目标** | 目标标题 / title | 文本 | 如"R2 底盘减重 2kg" | 该行整行不展示 |
| **关键结果** | KR | 文本 | 可量化的验收口径 | KR 列空白 |
| **负责组** | 组别 / 小组 / group | 单选/文本 | 组名与队员名单表一致（用于按组聚合） | 归入"未分组" |
| **截止日期** | 截止时间 / deadline / 日期 | **日期** | 必须是日期类型 | 时间基准缺失 → 永远不标红也永远不标绿（风险口径失效） |
| **完成度** | 进度 / progress | 数字/进度 | 0–100 或 0–1 小数 | 进度条空白，无法判风险 |
| **状态** | status | 单选 | `进行中 / 已完成` | 仅靠完成度=100 判达标 |

## 五、其他表（组长可能涉及）

| 表 | 推荐列名（识别别名） | 类型 |
|---|---|---|
| 队员名单（members） | **组别**（小组/部门/group） | 单选/文本；另有「权限角色」列用于登录角色判定（队长/财务/指导），见配置手册 |

| 财务报销（finance） | 由报销流程自动写入，组长无需手工维护 | — |

## 六、接入要求清单（新组建表 / 换表时）

1. **授权**：把目标多维表格右上角「分享」→ 添加协作者 → 搜索 NEC 工作台应用名 → 给「可阅读」。不做这步机器人拉数报 Forbidden。
2. **上报 table_id**：表格 URL 形如 `https://xxx.feishu.cn/base/<app_token>?table=<table_id>&view=...`，把 `app_token` 和每张表的 `table_id`（`tbl` 开头）发给管理员（或让 Agent 调 `config_dashboard action=set`）。
3. **建议五张表建在同一个 Base 里**（app_token 相同），config 只写一次。
4. **验证**：配置完成后打开门户首页，看任务/目标区是否渲染；命令行 `curl -s https://hub.newenergycoder.club/api/dashboard` 看各表 `error` 字段。

## 七、维护自检清单（每次改表后过一遍）

- [ ] 新列已在前 50 行的至少一行填了示例值
- [ ] 截止日期列是「日期」类型（不是文本！）
- [ ] 状态列没有空行；不做的任务是"已取消"而不是"搁置"
- [ ] 优先级取值是全大写 `P0/P1/P2`
- [ ] 目标表每行都填了截止日期和完成度
- [ ] 负责组/组别的组名与队员名单表写法一致
- [ ] 表格分享里 NEC 应用仍在协作者列表中（换 Base 后容易漏）

## 八、现象 → 原因速查

| 页面现象 | 大概率原因 | 改法 |
|---|---|---|
| 任务"截止/负责人"显示"—" | 列名不在识别别名里，或该列前 50 行全空 | 按 §三 改列名 + 填示例值；30 分钟后或 `?fresh=1` 刷新 |
| 明明逾期了首页不标红 | 截止日期是文本类型 | 改成「日期」字段类型 |
| 已做完的任务还在"未完成"里 | 状态词不含完结关键词（如"搁置""评审通过"） | 状态改成"已完成/已取消" |
| 目标全部显示"⚠ 风险"或全不显示风险 | 截止日期缺失，时间基准算不出 | 补齐目标表截止日期 |
| 首页数据半小时不更新 | 正常，KV 缓存 30 分钟 |  urgent 时 `?fresh=1` |
| 整表报错 Forbidden | 应用被移出协作者 / 换了新 Base 没授权 | §六 第 1 步重做 |
| 改完角色/组名 1 分钟没生效 | 角色缓存 60 秒 | 稍等即可 |
